## 1. 架构总览

### 1.1 数据流

```
用户消息 → AI(LLM) → Function Calling → ToolExecutor → 文件生成 → 返回文本结果
                                                         ↓
                                                   AI 收到结果 → 生成最终文本回复 → 宠物气泡显示
```

### 1.2 关键文件

| 文件 | 职责 |
|------|------|
| `Services/SkillManager.cs` | 定义 42 个工具的声明（名称、描述、参数 schema） |
| `Services/ToolExecutor.cs` | ~2600 行，执行所有工具的核心逻辑 |
| `Models/ChatMessage.cs` | `ContentItem` 返回类型（仅支持 `text` / `image_url` / `video_url` / `input_audio`） |
| `Services/ChatBridge.cs` | 编排对话循环，将工具结果注入 AI 上下文 |

### 1.3 依赖库

| 库 | 用于 |
|----|------|
| DocumentFormat.OpenXml | PPTX / XLSX / DOCX 生成与读取 |
| iTextSharp (LGPL) | PDF 生成与读取 |
| ZXing.Net | 二维码生成 |
| System.Drawing | 截图 |

### 1.4 工具结果呈现方式

当前**仅有一种**呈现方式：工具执行后返回 `List<ContentItem>`（纯文本），AI 收到文本结果后生成一段回复告诉用户"文件已保存到 XXX"。**没有：**
- 文件预览（WebView2 内嵌预览或 WPF 控件预览）
- 缩略图
- 文件下载/保存对话框
- 自动打开文件

### 2.1 create_ppt — PPT 生成

**工具定义：**

```csharp
// 参数：title(string), slides(array[{type, title, content, image_url}]), save_path(string)
```

#### ✅ 已实现

- 标题页（大标题 + 副标题）
- 内容页（标题 + 正文段落）
- 列表项（`•` 前缀）
- 从 URL 下载并嵌入图片（PNG）
- 文件路径清理（SanitizeFilePath）

#### ❌ 缺失 / 不完善

| 功能 | 严重程度 | 说明 |
|------|----------|------|
| **表格** | 🔴 高 | 无法创建任何表格，这是 PPT 中最常用的元素之一 |
| **图表** | 🔴 高 | 无柱状图、饼图、折线图支持 |
| **文本样式** | 🔴 高 | 无颜色、无字号变化、无对齐（左/中/右）、无粗体/斜体切换 |
| **主题/模板** | 🟡 中 | 使用空白的 SlideMaster，无任何设计模板；所有幻灯片白底黑字 |
| **幻灯片编号/日期/页脚** | 🟡 中 | 缺少 |
| **SmartArt / 图示** | 🟡 中 | 无法创建流程图、组织结构图等 |
| **形状** | 🟡 中 | 无法添加圆形、矩形、箭头等基础形状 |
| **幻灯片切换/动画** | 🟢 低 | 没有过渡效果 |
| **演讲者备注** | 🟢 低 | 缺少 |
| **超链接** | 🟢 低 | 文本无法添加可点击链接 |
| **多栏布局** | 🟢 低 | 所有内容单栏从上到下堆叠 |
| **本地图片** | 🟡 中 | 仅支持 URL 图片，不支持本地路径 |
| **非 PNG 图片** | 🟢 低 | 硬编码 ImagePartType.Png |
| **视频/音频嵌入** | 🟢 低 | 不支持 |

**代码质量问题：**
- `AddPptImage` 中异常被静默吞掉（`catch { }`），用户不知道图片加载失败
- 所有文本硬编码 `FontSize = 1800`（18pt），无动态调整
- 内容为数组时每个元素固定间距 `y += 35`/`y += 110`，不考虑文本实际长度
- 无文本溢出处理

### 2.5 read_* 读取工具

四个读取工具（`read_ppt`、`read_pdf`、`read_excel`、`read_word`）的实现相对合理：

- **read_ppt**：遍历所有 Slide → Shape → TextBody → Paragraph → Text，提取纯文本 ✅
- **read_pdf**：PdfReader 逐页提取文本 ✅
- **read_excel**：遍历 Sheets → Rows → Cells，正确处理 SharedStringTable ✅
- **read_word**：遍历 Body → Paragraph → Run → Text，提取纯文本 ✅

**共有缺陷：**
- 全部只提取文本，丢失表格、图片等结构化信息
- 无分页/分段标记，所有文本连成一片

## 3. 共性问题

### 3.1 工具定义层面

| 问题 | 影响 |
|------|------|
| 参数 schema 过于简化 | AI 不知道可以传颜色、字号、对齐等参数，自然不会用 |
| 无 output type 标识 | 返回结果都是 `text` 类型，调用方无法区分"生成了文件"和"返回了信息" |
| 无文件路径安全机制 | AI 可能生成任意路径，存在覆盖系统文件的风险 |

### 3.2 结果呈现层面

```
当前流程：工具执行 → 返回文本"文件保存到 XXX" → AI说"文件已保存到 XXX"
```

**完全缺失的能力：**
- ❌ 文件内嵌预览（WebView2 加载 Office/PDF）
- ❌ 缩略图预览
- ❌ 一键打开文件按钮
- ❌ 保存对话框（用户选择保存位置）
- ❌ 文件大小/页数等元信息反馈

### 3.3 错误处理

- 所有 `create_*` 方法中图片下载失败的 `catch { }` 完全静默
- 字体缺失时静默回退，无任何警告
- 磁盘空间不足、路径无权限等异常只有笼统的 `"xxx 执行失败: ex.Message"`

### 3.4 字体依赖

- PDF：硬编码依赖 SimSun（宋体），非 Windows 中文系统无法正常显示
- PPT/Word：未指定中文字体，依赖应用程序默认字体

### 3.5 Excel 的 Bug

`ExecuteCreateExcelAsync` 中将 `sheets.Append(sheet)` 放在了 `foreach` 循环内部（第 1194 行附近），导致每个 sheet 创建时都会重新 append 整个 Sheets 集合。正确做法应该是在循环外一次性创建 Sheets 并 append 所有 Sheet。

#### 表格支持（优先级最高）

为 **create_ppt**、**create_pdf**、**create_word** 统一增加表格参数：

```json
{
  "type": "table",
  "headers": ["列1", "列2", "列3"],
  "rows": [
    ["数据1", "数据2", "数据3"],
    ["数据4", "数据5", "数据6"]
  ],
  "style": "default"  // 可选
}
```

**实现要点：**
- **PDF (iTextSharp)**：`PdfPTable` 类，简单直接
- **Word (OpenXml)**：`WP.Table` + `WP.TableRow` + `WP.TableCell`
- **PPT (OpenXml)**：`A.Table` + `A.TableRow` + `A.TableCell`（DrawingML 表格）

#### Excel 数字/日期类型支持

扩展单元格数据类型：

```json
{
  "headers": ["姓名", "年龄", "入职日期", "薪资"],
  "data": [
    ["张三", {"type": "number", "value": 28}, {"type": "date", "value": "2023-01-15"}, {"type": "currency", "value": 15000}]
  ]
}
```

**实现要点：**
- `CellValues.Number` + 数字格式字符串（`#,##0.00`、`yyyy-mm-dd`）
- `CellValues.Date` 并非标准，实际用数字格式 + OADate 值

#### Excel 列宽自动适配

```csharp

public record ContentItem
```

#### C. 保存路径安全策略

```csharp
// 限制 AI 只能保存到安全目录
private static readonly string[] AllowedRoots = {
    Environment.GetFolderPath(Environment.SpecialFolder.Desktop),
    Environment.GetFolderPath(Environment.SpecialFolder.MyDocuments),
    Path.Combine(pluginDir, "exports")
};

private static bool IsPathSafe(string path)
{
    return AllowedRoots.Any(root => 
        Path.GetFullPath(path).StartsWith(Path.GetFullPath(root), 
            StringComparison.OrdinalIgnoreCase));
}
```

## 5. 技术选型建议

### 5.1 PDF 库迁移：iTextSharp → iText 7 Community 或 PdfSharp

| 对比 | iTextSharp (当前) | iText 7 Community | PdfSharp / MigraDoc |
|------|-------------------|-------------------|---------------------|
| 维护状态 | 停止维护（安全漏洞） | 活跃 | 活跃 |
| 许可 | LGPL（有风险） | AGPL（需注意） | MIT |
| 中文字体 | 依赖系统 | 可嵌入 | 可嵌入 |

### 现状评级

### 核心结论

当前 PetChat 的文档生成工具 **搭建了基本框架但远未达到"全功能"水平**。最短路径是：

1. **先修 bug**（Excel 多 sheet、静默 catch）→ 10 分钟
2. **加表格**（PDF/Word/PPT 统一）→ 4 小时
3. **加数字类型**（Excel 数值/日期）→ 2 小时
4. **换 PDF 库**（PdfSharp/MigraDoc → 字体嵌入 + 页眉页脚）→ 6 小时
5. **加文本样式**（粗体/颜色/字号）→ 4 小时

累计约 **16 小时** 的开发量即可将四个生成工具从 C/D 级提升到 B+/A- 级，覆盖 80% 的实际使用场景。
