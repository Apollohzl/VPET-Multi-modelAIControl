# 2026-07-28 工作日志

## 修复：Key配置页保存 key 后余额查询报 404

### 现象
用户在设置页【Key配置】输入并保存 API Key 后，余额查询结果总是 404。

### 根因（已定位并修复）
- 真正的后端在 `plugin/endpoints.lps` 中配置为自定义网关：
  - `models_url#https://hzliflow.ken520.top/api/ai/models`
  - `chat_url#https://hzliflow.ken520.top/api/v1/chat/completions`
  - `balance_url#https://hzliflow.ken520.top/api/account/balance`
  - `api_key_in_body#true`
- 但 `src/Services/ApiClient.cs` 的 `GetBalanceAsync` 把余额地址**硬编码**为 `https://gen.pollinations.ai/account/balance`，完全忽略了 `balance_url`；`src/PetChatPlugin.cs` 的 `LoadPlugin` 也硬编码同一地址、并未从 endpoints.lps 读取。
- 实测：网关 `hzliflow.ken520.top/api/account/balance` GET → **200**（`{"balance":...}`）；`gen.pollinations.ai/account/balance` 对网关 key 返回 401/404。余额请求打到错误主机 + 用网关 key → 404。

### 修复（3 个文件）
- `PetChatPlugin.cs`：`_balanceUrl` 改为从 endpoints.lps 读取 `balance_url`（缺失回退 pollinations 官方）；新增 `_apiKeyInBody` 读取 `api_key_in_body`；构造设置页时一并传入。
- `UI/PetChatSettingPage.cs`：构造函数新增 `bool apiKeyInBody` 参数并保存；`LoadBalanceAsync` 调用 `ApiClient.GetBalanceAsync(apiKey, _balanceUrl, _apiKeyInBody)`。
- `Services/ApiClient.cs`：`GetBalanceAsync` 新增 `balanceUrl`/`apiKeyInBody` 形参（带默认值，向后兼容）；用传入的 balanceUrl 发请求；`apiKeyInBody=true` 时额外把 key 作为 `API_Key` 查询参数发送（GET 无 body），同时保留 Bearer 头兼容官方接口。

### 验证
- curl 实测网关余额接口 GET → 200，证明改用 `balance_url` 即可消除 404。
- 无法在沙箱 `dotnet build`（缺 VPet SDK 引用），已做人工语法/调用一致性核对：唯一调用点已同步、旧调用 `GetBalanceAsync(apiKey)` 仍可用默认值编译。

- 环境有 dotnet 8.0.422（`/c/Program Files/dotnet/dotnet`）；VPet SDK 在 `F:\SteamLibrary\steamapps\common\VPet`，csproj 的 `VPetPath` 回退命中，可正常 build（之前误判"沙箱无法 build"）。
